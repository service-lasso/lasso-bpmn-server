# Dependency Audit

The canonical audit target is the packaged runtime app generated by `scripts/package.mjs`.

Do not treat `app/package.json` as the release dependency contract. The package script copies the app into `output/package/<version>/<platform>/payload/app`, writes the runtime `package.json`, runs `npm install --omit=dev --ignore-scripts`, and then archives that staged payload.

## Current Runtime Dependency Position

- `bpmn-server` is packaged at `2.3.8`.
- `mongoose` is packaged at `6.13.11`; this includes the fix for [GHSA-664h-wqgq-64gw](https://github.com/advisories/GHSA-664h-wqgq-64gw), which affects Mongoose versions before `6.13.10`.
- `@sendgrid/mail` is explicit at `8.1.6` because the app delegate can send mail when `SENDGRID_API_KEY` is set.
- The unused `v` package is not included because it only pulled in the vulnerable `simple-websocket` and `ws` tree.
- The embedded `/mocha` debug runner is disabled with HTTP `410` so the service does not ship a test runner as production runtime code.

## Verification

`npm test` performs these checks:

- packages the current platform artifact;
- runs `npm audit --omit=dev --ignore-scripts --json` against the extracted packaged runtime app and requires `0` vulnerabilities;
- downloads and starts the latest released `lasso-mongo` dependency;
- starts the packaged BPMN Server against MongoDB;
- checks `GET /healthcheck`, `GET /`, disabled `GET /mocha`, and `GET /api/engine/status?apiKey=typerefinery`.

## Upgrade Notes

`bpmn-server` `2.x` requires explicit `cacheManager` and `scriptHandler` configuration entries. The packaged app uses `NoCacheManager` and `ScriptHandler`, which preserves the existing Service Lasso runtime behavior while satisfying the newer BPMN Server configuration contract.
